# aliens_nex

Русская версия основной документации проекта **NEX-1**.

> Основной и нормативной документацией проекта является английская версия. Если между английским и русским текстом возникает расхождение, до синхронизации переводов приоритет имеет английская версия.

NEX-1 — экспериментальный минимальный, архитектурно-независимый, статически типизированный язык для компактной передачи программ между системами, у которых заранее нет общего языка программирования, архитектуры процессора, ABI, операционной системы или текстовой нотации.

NEX-1 v0.1 сейчас определяет:

- шесть конструкторов Core-термов: `Var`, `Lam`, `App`, `Let`, `Nat`, `Prim`;
- нумерацию de Bruijn с нуля, поэтому имена связанных переменных не передаются;
- rank-1 let-полиморфизм в стиле Hindley-Milner;
- натуральные числа, функции, произведения, суммы и unit;
- явную общую рекурсию через `fix`;
- одиннадцать фиксированных Core-примитивов;
- каноническое префиксное бинарное wire-представление;
- эталонную слабую семантику call-by-name;
- жёсткое разделение универсального Core и машинных/системных профилей.

## Цель проекта

NEX не пытается минимизировать только интерпретатор или только длину исходного текста.

Оптимизируемая величина — суммарная информационная стоимость:

```text
cost = specification + bootstrap implementation + transmitted programs
```

Поэтому проект не сводит автоматически всё вычисление к SKI-комбинаторам или машинным инструкциям. Рабочая гипотеза состоит в том, что небольшой типизированный lambda-core с индексами de Bruijn и прямым бинарным представлением данных может дать лучший общий баланс.

Это пока именно гипотеза. Она должна быть проверена измерениями против альтернативных представлений.

## Главная идея

NEX разделяет три уровня:

```text
удобный frontend
      ↓
канонические NEX-термы
      ↓
бинарное wire-представление
```

Человеческий синтаксис не является самим языком передачи.

Разные цивилизации, платформы или инструменты могут иметь разные frontends, но обмениваться одной и той же канонической NEX-программой.

Имена связанных переменных, пробелы, ключевые слова и форматирование в wire-представление не входят.

## Что намеренно не входит в Core v0.1

Core v0.1 не определяет:

- указатели и изменяемую машинную память;
- файлы, сокеты, дисплей, клавиатуру и системные вызовы;
- Unicode и строки;
- числа с плавающей точкой;
- потоки и атомарные операции;
- исключения, объекты, классы и модули;
- человеко-ориентированный исходный язык.

Эти возможности должны появляться в библиотеках, frontend-слоях или явно определённых execution profiles, а не загрязнять универсальный Core.

## Как принимаются архитектурные решения

Репозиторий является источником истины проекта.

Архитектурные решения, отвергнутые варианты и отложенные идеи фиксируются в ADR. История чатов не используется как долговременная архитектурная память.

Внешние технические источники, которые существенно влияют на спецификацию, ADR, алгоритмы, выбор стандартов или benchmark-baseline, фиксируются в `docs/SOURCES.md` согласно ADR-0004.

Работа строится по циклу:

```text
Problem
  -> Contract
  -> Invariant
  -> Failing test / executable example
  -> Implementation
  -> Verification
  -> Diff review
  -> Status checkpoint
```

## Ближайший этап

Первый implementation milestone намеренно ограничен wire-слоем:

1. реализовать самоделимитирующийся код `U(n)`;
2. реализовать канонический encoder/decoder `Term`;
3. добавить фиксированные golden/conformance vectors;
4. доказать round-trip автоматическими тестами;
5. детерминированно отвергать некорректные кодировки.

Только после этого отдельными этапами добавляются:

- проверка области de Bruijn;
- Algorithm W / вывод типов;
- evaluator.

Текущая точка продолжения всегда записывается в `docs/STATUS.md`.

## Исследовательская база

NEX-1 использует проверенные идеи из существующей теории и практики:

- индексы de Bruijn;
- Binary Lambda Calculus;
- вывод типов Hindley-Milner;
- PCF-подобную типизированную общую рекурсию;
- разделение переносимого вычислительного ядра и взаимодействия с окружением.

Поддерживаемый реестр источников с пояснением того, что именно NEX берёт из каждого источника, находится в [docs/SOURCES.md](docs/SOURCES.md). Первичные ссылки также приводятся в спецификации и ADR там, где это уместно.

## Ограничение на заявления проекта

Пока нет измерений, нельзя считать установленными утверждения вроде:

- «NEX — самый маленький язык»;
- «NEX даёт самый компактный код»;
- «bootstrap занимает X байт»;
- «NEX лучше BLC/SKI/WebAssembly по размеру».

До появления воспроизводимых экспериментов это гипотезы, а не факты проекта.
