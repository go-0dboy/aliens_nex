## Question

Can unchanged NEX-1 v0.1 implement a non-trivial transformation between its canonical binary wire and the accepted operational Term representation, in both directions, without returning an opaque input wire or delegating encoding decisions to a host callback?

The accepted representation is:

```text
FiniteBits      = (N -> N) * N
FiniteNatTokens = (N -> N) * N
```

Term tokens are:

```text
Var(k)   -> [0,k]
Lam(t)   -> [1] ++ t
App(a,b) -> [2] ++ a ++ b
Let(v,b) -> [3] ++ v ++ b
Nat(n)   -> [4,n]
Prim(p)  -> [5,p]
```

## Design

`decodeTerm`:

1. bounds the supplied bit function by the declared FiniteBits length;
2. traverses canonical wire using NEX-written parser logic;
3. computes the exact token count;
4. exposes a new indexed token stream that maps token indices to constructor tags/payloads;
5. rejects premature EOF and trailing wire separately.

It does not return the original bit stream as the decoded Term representation.

`encodeTerm`:

1. structurally validates one exact token tree;
2. computes its canonical wire length;
3. computes constructor-prefix and `U(n)` bits from token content;
4. exposes a new indexed bit stream with EOF after the exact length;
5. rejects empty/truncated/unknown-tag/trailing token representations as `MalformedMeta`.

No host callback supplies a missing constructor or integer-encoding decision.

## Required laws

For the frozen admitted surfaces:

```text
decodeTerm(encodeTerm(term)) == term
encodeTerm(decodeTerm(bits)) == canonical(bits)
```

Function-valued stream equality is checked extensionally: exact length, every element in range, and the required out-of-range sentinel. Observing only `Function` is not accepted.
