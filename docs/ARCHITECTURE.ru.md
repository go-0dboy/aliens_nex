# Архитектура

Русская версия архитектурного обзора NEX.

> Канонической является английская версия `docs/ARCHITECTURE.md`. Русский текст должен передавать тот же смысл естественным техническим русским языком.

Этот документ описывает текущую логическую архитектуру проекта и не заменяет нормативную спецификацию или ADR.

## Архитектура передачи и обучения

ADR-0017 разделяет протокол, с помощью которого получатель **осваивает** NEX, и стабильное вычислительное ядро, которым он должен уметь пользоваться после обучения.

```text
объявленные предпосылки получателя A
            |
            v
учебно-загрузочное сообщение NEX T
            |
            | постепенно устанавливает смысл
            v
  восстановленная компетенция NEX-1
            |
        самопроверка
            |
            v
       NEX-1 Core v0.1
            |
     канонические программы P
```

Учебное представление и каноническое представление Core являются разными архитектурными слоями намеренно.

В уроках могут использоваться избыточность, примеры, временная педагогическая нотация и поэтапные кодировки. Но ни одно из этих соглашений не считается бесплатным: если оно не входит в объявленные предпосылки получателя, его смысл должен быть установлен передаваемым учебным материалом.

NEX-1 Core остаётся неизменным, пока отдельный ADR о новой версии, подкреплённый экспериментальными данными, явно не изменит его.

## Уровни выполнения Core

```text
необязательный человеческий / машинный frontend
            |
            v
      канонические термы NEX
            |
     +------+------+
     |             |
     v             v
  вывод типов   бинарный кодек
     |             |
     +------+------+
            |
            v
       вычислитель Core
            |
            v
  дополнительные профили выполнения
            |
            v
      host / целевая машина
```

Человеко-ориентированный синтаксис не является каноническим бинарным форматом NEX и не предполагается известным неизвестному получателю.

## Модель Core

NEX-1 Core v0.1 имеет шесть канонических конструкторов термов:

```text
Var
Lam
App
Let
Nat
Prim
```

Система типов включает натуральные числа, единичный тип, функции, произведения, суммы и полиморфизм `Let` ранга 1. Общая рекурсия задаётся через `fix`.

Нормативная стратегия вычисления — слабый вызов по имени. Внутреннее устройство вычислителя не является переносимым наблюдением.

## Ответственность учебного слоя

Этап 6 вводит исследовательский слой над Core. Он отвечает за экспериментальные артефакты:

```text
граф зависимостей учебной программы
сериализацию уроков
педагогические примеры
передаваемые задания самопроверки
контрольные задачи на интерпретацию
контрольные задачи на построение программ
протокол эксперимента с получателем
классификацию скрытых предпосылок
учёт битов учебного сообщения
```

Учебный слой не имеет права незаметно предполагать знание:

- английского или другого естественного языка;
- Unicode, UTF-8, Markdown или JSON;
- семантики Go, Python или их сред исполнения;
- неуказанной математической или вычислительной нотации;
- универсальной машины или формального исчисления, отсутствующих в выбранном профиле предпосылок.

## Модули эталонной реализации Core

### `term`

Владеет каноническим представлением термов и правилами области действия индексов де Брёйна. Человеческий исходный язык сюда не входит.

### `wire`

Владеет каноническим бинарным кодированием/декодированием и самоделимитирующимся кодом натуральных чисел.

```text
encode : Term -> Bits
decode : Bits -> Result<Term, DecodeError>
```

### `types`

Владеет типами, схемами типов, подстановками, свободными переменными и унификацией.

### `infer`

Владеет выводом типов в стиле Algorithm W и окружением типов примитивов.

```text
infer : Term -> Result<TypeScheme, TypeError>
```

### `eval`

Владеет эталонным вычислением и реализует именно специфицированное наблюдаемое поведение.

### `primitives`

Владеет стабильной таблицей идентификаторов примитивов, их схемами типов и правилами редукции. Вывод типов и вычисление должны опираться на один авторитетный контракт примитивов.

### `conformance`

Владеет независимыми от языка векторами, связывающими спецификацию с переносимыми результатами кодирования, статической проверки и вычисления.

На этапе 6 выбранная часть этих примеров может стать заданиями самопроверки получателя. Передаваемый набор и его биты при этом учитываются явно.

### `bench`

Владеет воспроизводимыми измерениями. Результаты производительности и измерений не являются доказательством соответствия спецификации.

### `stage6`

Владеет артефактами планирования и будущих экспериментов по обучению. Этот каталог не является второй реализацией языка и не должен становиться альтернативным источником семантики Core.

## Направление зависимостей

Для эталонной реализации:

```text
term <- wire
term <- infer <- types
term <- eval
infer <- primitives -> eval
conformance -> публичные контракты Core
bench -> публичные контракты Core
```

Для учебного исследования:

```text
предпосылки получателя -> учебная программа
спецификация/conformance NEX -> уроки и самопроверка
учебная программа -> точная сериализация сообщения (в будущем)
сериализация -> точный битовый учёт (в будущем)
контрольные задачи -> эксперимент с получателем
```

Учебный слой может ссылаться на нормативный контракт Core, но Core не должен зависеть от учебной программы.

## Архитектурные ограничения

Без отдельного ADR и новой версии Core этап 6 не добавляет:

- новые конструкторы термов или идентификаторы примитивов NEX-1;
- несовместимые изменения бинарного формата;
- изменяемую память Core;
- системные вызовы и интерфейсы ОС;
- нативную генерацию кода;
- продуктовые возможности frontend;
- утверждения о self-hosting.

Учебный слой может оказаться неудачным, увеличиваться, менять порядок уроков или использовать временные педагогические кодировки, не расшатывая NEX-1 v0.1. Это разделение сделано специально: сначала проверяем, как научить уже определённой точной системе; меняем саму систему только тогда, когда данные показывают необходимость такого изменения.
